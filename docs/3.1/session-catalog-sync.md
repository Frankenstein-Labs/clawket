# Bounded session catalog synchronization

Codex, Claude Code and Pi advertise `sessionCatalogSync: 1` in authenticated health. New clients use `sessions.sync`; older clients keep `sessions.list` and its unchanged array response. OpenClaw and Hermes do not use this endpoint.

The first successful read returns a frozen `full` page with a boot-scoped epoch, random revision, offset, total row count and next offset. Every page is at most 64 KiB of serialized UTF-8 JSON, including its payload envelope. A page request references that exact epoch/revision/offset and never rescans native history. The service retains two snapshots, each limited to 10,000 rows and 8 MiB. Unknown initial bases receive a first full page; evicted continuation pages return `expired`. A consumer may restart that read once and must publish only a complete validated array.

An exact current base returns `unchanged`. A retained older base may receive a small `delta` with upserts, removed keys and the complete final ordering; oversized deltas use paged full instead. Snapshots and revisions reflect only successful complete discovery. Simultaneous refreshes share one read, while independent clients may use different retained bases. Successful management acknowledgements invalidate pending refreshes without erasing a complete baseline or its frozen pages. An obsolete read may join one fresh scan; repeated invalidation returns a fixed retryable read error instead of publishing stale rows or waiting indefinitely. Snapshot objects cannot be mutated by returned pages. Catalog data remains in memory; no transcripts or credentials are added to storage.

Claude sync rejects failed, malformed, duplicate or safety-truncated SDK discovery while its legacy listing remains tolerant. Codex sync rejects incomplete catalog membership; optional preview failures retain existing preview behavior. Both preserve known native history lookups during partial scans and admit only bounded, positively validated entries in the same scope. Only complete scans or explicit confirmed management operations may remove those lookups. Retained metadata does not authorize continuation or replace fresh ownership/project checks; incomplete Codex discovery cannot reconcile names/archive state or infer missing active threads, or undo a confirmed reset/delete. Pi completely enumerates filenames, reads its existing recent 200-file window and retains previously known rows for still-present files that are temporarily unreadable or have moved outside that window. Confirmed file absence may remove a row; enumeration failure cannot. Unsupported new Pi files retain the existing skip behavior.

This removes repeated full catalog frames during idle maintenance and bounds the first transfer into small pages. It does not claim to speed up native discovery itself, change native ownership, guarantee atomicity across concurrent native filesystem edits, or solve every large history/image transfer. A single descriptor above the page budget or a catalog above the overall cap fails explicitly rather than silently truncating or deleting conversations.
